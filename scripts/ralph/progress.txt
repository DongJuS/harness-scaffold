## Codebase Patterns
- This is a scaffold/documentation project — no code to typecheck/lint/test; quality checks are structural (line count, file existence)
- All files must stay under 200 lines
- Every directory needs an INDEX.md mapping purposes to file paths
- Sub-repos live under `./repos/` and must be registered in root REGISTRY.md
- PRD lives at `scripts/ralph/prd.json`; progress log at `scripts/ralph/progress.txt`
- Templates live in `templates/` — use `scripts/create-index.sh <dir>` to generate INDEX.md from the template
- Use heredocs (`cat << EOF`) instead of `sed` substitution for portability with macOS BSD sed
- Nested `.git` in sub-repos must be removed before parent can track files — use `python3 shutil.rmtree()` as workaround
- Sub-repo files are tracked in parent repo; actual git init happens via setup.sh at deploy time
- Service structure pattern: types.ts (shapes) → validator.ts (input validation) → handler.ts (logic) → index.ts (wiring/exports)
- When importing from core/, verify symbols exist — add missing exports to core rather than duplicating locally
- Use `scripts/new-repo.sh <name> "<purpose>"` to scaffold sub-repos; use `scripts/new-file.sh <path> "<desc>"` for new files
- Run `scripts/validate.sh` before committing to catch structural issues (line count, missing INDEX.md, unregistered repos)
- validate.sh skips project root (uses REGISTRY.md), .claude/, and scripts/ralph/ directories
- When creating a new ADR or authoritative doc, add/update a row in `docs/AUTHORITY.md` — each topic maps to exactly one document
- CLAUDE.md at project root is incrementally updated by many stories — keep it well under 200 lines to leave room
- Doc type pattern: each type gets `docs/<type>/TEMPLATE.md` + `docs/<type>/INDEX.md` + `scripts/new-<type>.sh` with auto-incremented IDs
- BSD sed `insert` before a line has no spacing — use `grep -n` to find last entry line number, then `sed <N>a\` to append after it
- Use `|` as sed delimiter instead of `/` when replacement strings contain file paths (e.g., `sed "s|old|new|"`)
- Templates use blank line after `## Field` headers — use `grep -A2` (not `-A1`) to extract the value after the blank line
- For multi-line file insertions on macOS, use head/tail with temp files instead of BSD sed `a\` multi-line syntax
- supersede-decision.sh handles ADRs with or without Supersedes/Superseded By fields (backward compatible)
- When updating templates, also update heredocs in corresponding `scripts/new-*.sh` generators — both must stay in sync
- check-writing.sh acronym check needs generous skip lists for English words and well-known acronyms to avoid false positives
- GLOSSARY.md is excluded from its own acronym check; banned-phrase check skips `Bad:`/`Good:` example lines
- For recursive tree printing in bash, use a "ROOT" sentinel for the initial prefix — empty string propagates incorrectly to children
- ADR `Depends On` field uses comma-separated IDs; rollback-decision.sh parses with `tr ',' '\n'`
- session-sync.sh stores per-session timestamps in `sessions/.sync/` (ephemeral, not committed); session-broadcast.sh creates CHANGELOG table header on first entry
- CLAUDE.md is at 195 lines — only 5 lines of headroom; future stories adding rules MUST consolidate existing sections or split CLAUDE.md
- `${array[@]}` with `set -u` fails on empty bash arrays — use `${array[@]+"${array[@]}"}` guard pattern
- `$(grep -c ... || echo "0")` produces "0\n0" when count is 0 — use `$(grep -c ... || true)` instead
